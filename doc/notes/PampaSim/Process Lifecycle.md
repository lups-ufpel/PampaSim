We've got a bit of a pickle. The `Process` class needs a PID to be instantiated, which is not a bad thing by itself. It means whenever we get a `Process` object, we can be sure that it already has a PID, and is not in a special pre-simulation state. Helps keep the invariants tight and invalid states harder to reach. But! And it's a big but: how do we keep track of the `ProcessViewModel`s for these not yet instantiated `Process`es? We can't use the PID. I decided to use the `Process.CreationData` object that `Process.Arrival` events carry.
